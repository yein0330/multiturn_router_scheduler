## 정의

- **호출 분류**: 세션 안의 실제 호출 순서를 따르며, 재시도를 포함한다.
  - `first_call`: 세션 첫 호출
  - `first_switch`: 세션에서 아직 쓰지 않은 모델로 처음 전환
  - `return`: 이전에 쓴 모델로 복귀
  - `stay`: 직전과 같은 모델
- **TTFT**: 클라이언트가 첫 텍스트 토큰을 받을 때까지의 시간이다. 대기, prefill, 첫 decode 단계를 포함하므로 **순수 prefill 시간이 아니다**.
- **생성 시간**: 호출 총 시간 − TTFT.
- **세션 지연**(기존 정의): 턴마다 라우터 + 게이트 + 퇴거 + 렌더링 + LLM 호출 + verifier를 더한 값. 이 정의 덕분에 아래 분해는 합이 정확히 맞는다.

## 4. 해석과 기존 서술 감사

- **[측정] long에서 P4가 P2보다 느린 원인은 "B 복귀 재계산"이 아니다.**
  - B 쪽 TTFT는 P4가 오히려 0.29 s 적다.
  - B 복귀는 50세션 전체에서 1회(0.095 s)뿐이다.
  - 지연 증가분 +0.23 s는 다음 항목의 합이다.
    - A 생성 +1.84 s, A TTFT +0.43 s, 라우터 +0.32 s
    - B 생성 절약 −2.08 s(short에서는 −3.44 s)
- **[측정] long에서 B 생성 절약이 작은 이유는 두 가지가 겹친 결과다.**
  - (a) A로 처리한 단계에서는 실제로 단계당 약 1.0 s를 아꼈다.
  - (b) B로 처리한 단계에서는 B가 P2보다 더 길게 썼다(+31토큰, 단계당 +0.59 s).
  - 여기에 재시도도 많았다.
- **[해석]** (b)는 B가 A가 만든 이력(더 긴 코드, 다른 오류) 위에서 답했기 때문일 수 있다. 하지만 경로가 다르면 요청 순서는 같아도 이력·재시도·답변 내용이 달라진다. 그래서 이 차이를 전환 자체의 인과 효과로 확정할 수 없다. 3절 주 실험과 4절 분기 실험이 이를 부분적으로 다룬다.
- **[측정] 여러 모델에 문맥을 계산하는 추가 비용**(long/retain, P4 − P2)은 다음과 같다.
  - A 쪽 첫 문맥 처리: A `first_call` TTFT 평균 0.41 s, 44세션
  - 미적중 토큰: +9.5K토큰/세션
  - 지연 기준으로는 A TTFT +0.43 s/세션이다. B 생성 절약 2.08 s의 약 1/5이다.
- **[측정] 총량과 순량을 구분해야 한다.**
  - 총량으로는 생성 항(A +1.84 s, B −2.08 s)이 가장 크다. 하지만 서로 거의 상쇄되어 순 −0.24 s만 남았다.
  - 순 지연 증가 +0.23 s는 A 쪽 첫 문맥 처리(+0.43 s)와 라우터(+0.32 s)가, B TTFT 감소(−0.29 s)와 작은 생성 절약(−0.24 s)을 넘어선 결과다.
  - 즉 long에서 P4의 지연 이득이 사라진 것은 두 가지 때문이다.
    - (a) 생성 절약이 작아졌다. long에서 A의 토큰당 생성이 느려졌고(4.5 → 5.9 ms), B 단계 출력이 길어졌다.
    - (b) A 문맥 처리와 라우터라는 고정비가 남았다.
  - 여기서 문맥 비용은 B **복귀**가 아니라 A의 **최초** 문맥 계산이다.
