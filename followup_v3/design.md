## 단계 0 (동결: 2026-10-16 17:10 KST, 실행 전)

### 0-1. 사후 선택 여지
- 입력: `followup_v2/results/analysis_main/sessions_all.csv`. v2 50세션, 조건 short/long(retain)이다. P10은 short만 있다.
- 품질 제약: 세션 i에서 요청 통과율 q_i(π) ≥ q_i(BBBBB). 세션 전부 성공 S는 별도로 보고한다.
- 후보 집합:
  - F2 = {AAAAA, BBBBB}
  - F6 = 고정 schedule 6개
  - F6+ = F6 ∪ {P4, P6}, short에서는 P10도 포함
- 사후 선택 값: 세션마다 제약을 만족하는 정책 중 최소 지연을 고른다. BBBBB가 항상 제약을 만족하므로 해는 존재한다.
- 스칼라화: μ ∈ {0.5, 1, 2, 4}에서 세션마다 argmax μ·q − J/T_ref를 고른다.
  - T_ref = 해당 조건 평가 BBBBB의 평균 지연. **평가 데이터로 정한 사후 정규화**로 표시한다.
- **이 값들은 "실행한 정책 경로 집합 내 사후 최선"이다.** 경로를 이어 붙이지 않는다. 전역 oracle이나 달성 가능한 상한이라고 부르지 않는다.
- cross-fit(시나리오 정보를 부여한 진단 기준선):
  - 시나리오마다 세션 10개를 5/5로 나눈다.
  - 선택 반쪽에서 제약 기준으로 하나의 schedule을 고른다. 선택 반쪽의 평균 q가 BBBBB 평균 q 이상인 schedule 중 평균 지연이 최소인 것이다.
  - 평가 반쪽에서 그 schedule의 평균 지연·q·S를 구한다.
  - μ 기준도 같은 절차로 한다.
  - 분할 200개(seed 0–199)의 평균을 보고한다. 이 200개는 독립 표본이 아니다.
  - 템플릿 그룹 제약: 평가 도메인은 3개뿐이라 도메인 단위 분할은 하지 않고, 세션 단위로 나눈다(한계로 보고).
- 불확실성: 시나리오 층화 세션 bootstrap(2000)으로 구한다. cross-fit 값은 재표집마다 선택·평가 절차 전체를 다시 실행한다.
- 분기 표: v2 분기 40점의 남은 단계당 지연·품질 → `branch_per_remaining_stage.csv`
- 산출물: `results/stage0/headroom_definition.json`, `oracle_summary.csv`, `oracle_by_scenario.csv`, `branch_per_remaining_stage.csv`

### 0-2. "A로 충분한가" 신호 탐색 (탐색, 학습 아님, 결과는 [가설])
- 레이블:

- 시점을 분리한다.
  - **initial-pre-call**: 첫 요청의 연산군(요청 문장에서 결정적으로 정해지는 연산 종류; 생성기 메타데이터와 1:1이므로 관측 가능 대리로 표시), 첫 요청 토큰 길이, 문맥 조건. 첫 요청은 항상 [New task]이므로 그 특징은 상수라 뺀다. verifier 존재는 이 시점에 관측할 수 없으므로 뺀다.
  - **after-first-A**: 위 특징에 더해 첫 A 응답의 생성 토큰 수, 첫 verifier 결과(S5에서만 관측, 그 외에는 "없음"). 이 시점의 특징을 쓰면 이미 낸 A 호출 비용을 포함해야 한다(표에 그 비용을 함께 표시).
- 데이터 분할:
  - short: dev의 P1/P2 쌍(dev_smoke 10 + dev_calib_sessions 20 = 30세션)으로 맞추고 eval 50세션에서 보고한다.
  - long: dev 쌍이 2세션뿐이므로 eval에서 시나리오 단위 leave-one-out으로 한다(탐색).
- 모델: 특징별 단변량 AUC, L2 로지스틱 회귀(C=1.0 고정, 튜닝 없음).
- 보고: 클래스 비율, n, AUC, Brier, 2–3구간 보정표.

### 0-3. 라우터 점수 (선택 기능)
- [측정 완료, 실행 전 점검] R tokenizer에서 `SMALL` = [SM, ALL], `LARGE` = [L, ARGE]로 다중 토큰이다. 기록된 R 출력 3,937건은 모두 정확히 "SMALL" 또는 "LARGE"였다.
  - 따라서 첫 토큰 logprob 차는 응답 점수로 쓰지 않는다.
- 점수 정의:
  - 같은 R 프롬프트(router.py 그대로 재구성) 뒤에 후보 완성 문자열 `SMALL<|im_end|>`, `LARGE<|im_end|>`를 붙인다.
  - vLLM `prompt_logprobs`로 후보 토큰들의 조건부 로그우도 합을 각각 얻는다(후보당 1회 호출, max_tokens=1).
  - margin = ll(LARGE) − ll(SMALL).
  - 강제 선택이나 제약 디코딩은 쓰지 않는다.
- 재현 점검:
  - (a) 재구성 프롬프트의 토큰 수 = 기록된 input_tokens. 기록에 프롬프트 해시가 없어 해시 대조는 불가능하다.
  - (b) 재구성 프롬프트로 greedy 재생성한 결과 = 기록된 raw.
  - (c) sign(margin)에 따른 선택 = 기록된 결정.
  - (b)나 (c)가 99% 미만이면 점수 분기를 중단하고 원인을 보고한다. decision-only 분석은 계속한다.
- 대상: 격리 자료를 제외한 모든 유효 라우터 호출. dev 실행, evalA, B2 3개, followup_v1 newpol.
- "B 필요" 레이블은 **동일 상태 A/B 결과**에서만 붙인다. followup_v1 분기(초기 10점, 전환 20점)와 v2 분기 40점의 다음 호출 결과가 그것이다. report.md §4의 경로 간 레이블은 "다른 경로 대리 레이블"로 따로 표시해서 보고한다.
- 백분위 매핑: dev 라우터 호출의 margin으로 경험적 CDF를 만들고, ρ = F_dev(margin)으로 정의해서 동결한다. 백분위는 정확도 확률이 아니다.
- 추가 비용: 점수 하나에 R 호출 2회(prompt 처리만)가 더 든다. 이 구현은 "추가 LLM 호출 없음" 조건을 충족하지 않는다고 표시한다.
- GPU: R 서버(GPU 3)만 띄운다. 실행은 flock 아래에서 한다.

### 1-3. 프로파일·비용 표현·관문 1
- 격자: 문맥 {1K, 4K, 8K, 16K, 24K} × 재사용 {0, 0.5, 0.95} × 출력 {16, 48, 128, 320} × {A, B} × 3회 = 측정 360회, 준비 호출 240회.
  - 프롬프트: smoke always_B long 세션들의 실제 메시지를 이어 붙이고 메시지 경계에서 자른 것이다(pure-system, 같은 token prefix).
  - 출력은 강제 길이(min_tokens = max_tokens = g, ignore_eos)로 측정하며 비용 보정 전용이다.
- 적합: 모델별로 C0, C1, C2를 최소제곱으로 적합한다. C3는 fit cell 중앙값의 3선형 보간이고, 범위 밖이면 C2로 대체한다.
  - **hold-out**: 문맥 8K 또는 출력 48인 모든 cell(cell 단위). 반복 단위로 나누지 않는다.
  - 오차 지표: 호출 총지연 MAE와 p95 절대오차.
- 결정 계산 입력:
  - ŷ (smoke 고정): A 35.0, B 36.8토큰
  - N̂ (smoke 고정, 결정 지점부터 남은 호출 수): short 9.0, long 11.8
  - Δ (호출당 문맥 증가, smoke): short 98, long 378토큰
- 결정 지점: dev L0 실행에서 현재 모델 ≠ R 추천인 호출이다. 첫 호출은 현재 모델이 없으므로 제외한다.
- 비용만 비교한 선호(학습된 q 없음, 정책 결정이 아님):
  - follow iff Ĉ(추천) < Ĉ(현재)
  - h=1: Ĉ = C(m, ℓ, ĉ_m, ŷ_m), ĉ_m = 클라이언트 캐시 예측
  - h=N̂: Ĉ = C(m, ℓ, ĉ_m, ŷ_m) + (N̂−1)·C(m, ℓ+Δ, ℓ, ŷ_m). 이후 호출 비용을 상수로 근사한 것이며 한계로 기록한다.
- 보고: 표현 쌍(C0–C1, C0–C2, C0–C3, C1–C2, C1–C3, C2–C3) × 문맥 × h × 추천 방향별 불일치 비율과 분모, 전체 호출 대비 비율.
- 소량 paired 측정:
  - 대상: dev 결정 지점 중 C1과 C2/C3가 엇갈리는 지점(없으면 |Ĉ차|가 작은 지점)에서 (문맥, 방향) 층별 해시 순서로 최대 24점.
  - 상태를 복원하고 keep/follow 다음 호출을 각각 3회(AB/BA 균형) 측정해 실측 부호를 확인한다.
- **관문 1** (모두 충족해야 단계 2 후보):
  - (a) C1–C2 또는 C1–C3 불일치가 한 조건 이상에서 결정 지점의 15% 이상이고, 그 셀의 분모가 30 이상. C0 쌍은 따로 보고한다.
  - (b) dev에서 S(always_B) − S(always_A) ≥ 0.15
  - (c) q_A ≥ q_B 세션 비율이 20–60%(조건별). 둘 다 0인 세션 비율도 함께 보고한다.
