# followup_v5 설계 (단계별 동결 기록)

- 지시서: 사용자 지시(2026-10-20) 0–8절.
- 범위: 단계 0–2를 실행하고 보고서를 쓴 뒤 멈춘다. 단계 3은 사용자 확인 후에만 한다. 어댑터 학습·PPO·eval 실행은 하지 않는다.
- 기본 인터페이스: T1 스키마, R1 라우터(`followup_v4/src/iface.py`). 모델·서버 설정은 `configs/models.json` 그대로다.
- 표기: [측정] / [추정] / [가설].

## 단계 0 (동결: 2026-10-20 13:00 KST, 실행 전)

### 0-a. T1에서 B 품질 하락 원인 분리
- **사전 결정(지시서와 다름)**: T1-full과 T0의 항상 B는 다시 실행하지 않는다.
  - 같은 10세션 × 2문맥 결과가 v4 단계 A에 이미 있고(`followup_v4/results/stageA`), 운영 규칙이 "기존 실험을 다시 돌리지 않는다"다.
  - 이 실행기는 결정론적이다(v4에서 기존 조건 60실행 텍스트 60/60 동일).
- 새로 실행: **T1-min** 항상 B, v4 단계 A 10세션 × 2문맥 = 20실행(약 300호출).
  - T1-min = T0 설명문을 그대로 두고 구조 제약만 추가한 스키마. 구조 제약은 filter `conditions.items` {column, op(enum), value} required, aggregate op enum이다.
  - 도구 정의를 포함한 프롬프트 길이: T0 602 / T1-min 688 / T1 783토큰.
- 판단 규칙(사전): T1-min 항상 B의 요청 정답률이 T0 항상 B와 같은 세션 짝 비교에서 −0.05 이내이고 T1-full이 그보다 낮으면, "T1-full의 설명문이 B를 해쳤다[가설]"로 보고한다. 어떤 결과든 S1·S2는 T1으로 진행한다.

### 0-b. train 수확
- train 풀: 기존 v3 train 50세션(시나리오당 10)에 같은 생성기·seed 규칙(63000 + 100·j + i)으로 i = 10–19를 추가해 100세션을 만든다(`data/train_pool.jsonl`).
  - 기존 50세션 재현은 50/50 동일함을 확인했다.
  - 늘린 이유: 기존 train 50세션으로는 N=60을 채울 수 없다.
- 선정: 시나리오마다 sha256('v5train|'+session_id) 순 12세션, 총 60세션(`configs/train_harvest_sessions.json`).
- 실행: 60세션 × {short, long} × {항상 A, 항상 B}, T1 = 240실행. 순서는 seed 503으로 섞는다.
- 호출 수 예상: smoke(1세션 × 2문맥 × 2정책) 측정 후 아래에 기록한다.

### 0-c. 멈춤 조건
- 0-b에서 수확한 "첫 반복 상태"가 60개 미만이거나 "B 필요"(A 실패 & B 성공) 요청이 40개 미만이면 멈추고 보고한다.
- 첫 반복 = 항상 A 경로의 한 요청 안에서 모델 출력(assistant 텍스트)이 직전 호출과 완전히 같아진 첫 시점이다.

### 공통
- GPU 작업은 `followup_v3/run_locked.sh` 단일 실행기로 한다.
- 캐시 예측 불일치·복원 해시 불일치·반복 간 출력 변동이 0이 아니면 멈춘다.

### 0-b 호출 예상 (smoke 측정 후, 실행 전 기록)
- smoke: train-const-13, 4실행 81호출(항상 A short 18 / long 26, 항상 B short 21 / long 16).
- 예상: 60세션 × 81 ≈ 4,900호출(A/B). R 호출 없음.
- 0-a 예상: 20실행 × 약 15 ≈ 300호출.
- smoke 결과는 0-b에 섞지 않는다. 0-b는 같은 세션을 다시 실행하며, 결정론 점검을 겸한다.

## 단계 1 — S1 반복 감지 상향 × 넘길 이력 (규칙 동결: 2026-10-20 13:05 KST, 0-b 완료 전)

- 상태:
  - 항상 A(T1) 경로에서, 한 요청 안의 호출 출력(assistant 텍스트)이 직전 호출과 완전히 같아진 첫 시점을 찾는다.
  - 분기점은 그 호출의 도구 결과가 이력에 추가된 직후, 다음 모델 호출 직전이다.
  - 기록된 경로가 그 요청을 더 진행하지 않았으면(예산 소진·제출) 회복 기회가 없으므로 후보에서 제외하고, 그 수를 센다.
- 출처: dev = v4 단계 A T1 항상 A(10세션 × 2문맥), train = 0-b 항상 A(60세션 × 2문맥).
- 선정(`configs/s1_states.json`, 0-b 후 실행 전 commit):
  - (분할, 문맥) 층마다 sha256('v5s1|sid|ctx|call') 순으로 최대 20개, 서로 다른 세션을 우선해 최대 80상태를 고른다.
  - 분기 순서는 상태마다 seed 504로 섞는다.
  - sha256('v5s1rep|state_id') 순 첫 15상태는 한 번 더 실행한다(재현성 확인용, 표본에서 제외).
- 분기(`src/s1.py`): a0 A 계속 / a1 B 원 이력 / a2 B 반복 제거 / a3 B 상태 요약 / a4 A + 반복 알림 고정 문장.
  - 분기 모델을 그 요청이 끝날 때까지 유지하고, 그 요청 안에서는 라우터를 호출하지 않는다.
  - 이후 요청은 π₀ = T1에서 R1을 따른다. 수정된 이력이 그 시점부터 세션의 실제 이력이 된다.
  - a3 상태 요약은 프로그램으로만 만든다: 이전 요청의 제출값, 현재 handle 정의(관측된 filter 호출·결과에서 생성), 마지막 도구 결과, 현재 요청 문장. LLM 요약은 쓰지 않는다.
- 복원:
  - 항상 A 경로이므로 A 캐시만 기록된 프롬프트로 다시 채운다. B와 R은 비어 있다.
  - prompt 해시, 도구 상태 해시, 첫 호출의 기대·실제 적중을 기록한다. 복원 시간은 경로 지연에서 뺀다.
- 측정:
  - 현재 요청의 정답·호출 수·지연·도구 오류·재반복·B 출력 길이·실제 적중
  - 남은 세션 q_rem, S, J
  - 상태별 "B로 회복 가능"(a1–a3 중 하나라도 정답) 사후 표시
- 예산:
  - smoke 3상태(sha256('v5s1smoke|state_id') 순)로 측정한 뒤 예상을 여기에 기록한다.
  - 예상이 12K호출 또는 GPU 6시간을 넘으면 멈춘다.
- 멈춤: 복원 해시 불일치, 캐시 예측 불일치, 반복 간 출력 변동.

## 단계 2 — S2 요청 시작 판단 (규칙 동결: 2026-10-20 13:05 KST, 0-b 완료 전)

- 상태: 항상 A(T1) 경로의 각 요청 시작 직전(그 요청 첫 호출 전). 라우터 입력의 이력은 항상 A 경로의 이력이다(근사, 한계로 기록).
- 레이블(분석 전용):
  - B 필요 = 항상 A 오답 & 항상 B 정답
  - A 충분 = 항상 A 정답
  - 둘 다 실패
  - 주 분석은 둘 다 실패를 음성으로 두고, 제외한 분석도 보고한다.
- 입력(요청 시작 시 관측 가능한 것만):
  - 요청 문장(인터페이스 헤더 포함)과 follow-up 여부
  - 직전 요청의 제출 여부·예산 소진·반복 발생·도구 오류 수(항상 A 경로 기준)
  - 문맥 조건, 첫 요청 여부
  - 숨김 kind는 넣지 않는다.
- 예측기:
  - P0: R1 결정(생성)
  - P1: R1s(출력 레이블만 `A`/`B` 단일 토큰으로 바꾼 R1 변형)의 첫 토큰 logprob 차. vLLM `logprobs=20`을 쓰고, 후보가 상위 20개 밖이면 결측으로 둔다(0 대체 안 함). R1s argmax와 R1 결정의 일치율을 보고한다. 이 오프라인 측정에서는 R1과 R1s를 따로 호출한다. 실제 정책에서는 R1s 호출 하나가 결정과 점수를 함께 준다.
  - P2: 요청 문장 TF-IDF(train 문서 빈도 ≥ 2) + 관측 특징, L2 로지스틱 회귀. C ∈ {0.1, 1, 10, 100}을 dev AUC로 고른다(같은 dev에서 고르므로 낙관적이라고 표시).
  - P3(문장 인코더): CPU 가용 인코더 확인 후 선택한다. 하지 않으면 그렇게 보고한다.
- 분할(세션 단위):
  - train = 0-b 60세션 중 hold-out을 뺀 나머지
  - dev = v4 단계 A T1 10세션(도메인 hotel·gym, 문장 variant 1) + 0-b hold-out 10세션(시나리오마다 sha256('v5s2hold|'+id) 순 2개, variant 0)
- 보고: AUC, 정밀도 0.6에서의 재현율, R1 대비 개선, 숨김 kind 계열별 혼동표(분석용).
- 일반화 경고: 생성기의 난이도가 연산군으로 정해지므로 문장 분류기는 템플릿을 외울 수 있다. dev 성능은 "템플릿 내 일반화"로만 해석한다.
